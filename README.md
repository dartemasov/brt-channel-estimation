# Block Recurrent Transformer for channel estimation

  This repository provides a block recurrent transformer (BRT)-based neural network (NN) model for hybrid-field hybrid beamforming channel estimation in the THz band.

## Usage

  The channel generation script uses multiprocessing for efficient parallelization. To prevent overutilization, you may wish to disable NumPy’s internal parallelization by setting the following environment variables:

  ```bash
  export MKL_NUM_THREADS=1
  export NUMEXPR_NUM_THREADS=1
  export OMP_NUM_THREADS=1
  ```

  To run an experiment, use the `main.py` script with the appropriate arguments. For example, to run both train and evaluation modes on Cuda with default configuration parameters:
  
  ```bash
  python main.py --mode both --config configs/default.json --device cuda:0
  ```

  The parameters to operate in different setups:
  - `--mode`: `train` - only training is performed, `eval` - only evaluation is performed, `both` - training followed by evaluation (default: `both`);
  - `--config`: Path to your json file with configuration (default: `configs/default.json`);
  - `--device`: The device that you would like to use to train the model (default: `cuda:0` or `cpu`).

  Dataset configuration:
  ```json
 "dataset": {
          "set_size": 500000, 
          "miniset_size": 100, 
          "n_antennas": 1024,
          "n_rf": 4,
          "carrier_freq": 300e9,
          "n_subcarriers": 32,
          "bandwidth": 15e9,
          "n_paths_min": 5,
          "n_paths_max": 5,
          "los_path_len": 30,
          "scat_dist_min": 10,
          "scat_dist_max": 25,
          "snr_db_min": 0,
          "snr_db_max": 20,
          "n_workers": 80,
          "meas_mat_path": "data/CSmatrix1024_512_AoSA.npy"
  }
  ```

  Explanation of parameters:
  - `set_size`: number of channel/measurement samples for training per epoch;
  - `miniset_size`: the size of the subset that is generated by each parallel worker. Must be a multiple of `set_size`;
  - `n_rf`: number of RF-chains;
  - `carrier_freq`: carrier frequency in Hz;
  - `bandwidth`: bandwidth in Hz;
  - `n_subcarriers`: number of subcarriers;
  - `n_paths_min` and `n_paths_max`: minimum and maximum number of paths;
  - `los_path_len`: distance between transmitter and receiver in m;
  - `scat_dist_min` and `scat_dist_min`: minimum and maximum distance of scatterers in m;
  - `snr_db_min` and `snr_db_min`: minimum and maximum uplink SNR in dB;
  - `n_workers`: number of parallel channel generation workers;
  - `meas_mat_path`: path to channel channel measurement matrix.

  Configuration for the model:

  ```json
  "model": {
        "name": "BlockRecurrentTransformer",
        "n_ant": 2048,
        "n_time_steps": 5,
        "num_tokens": 2048,
        "dim": 2048,
        "depth": 3,
        "dim_head": 1024,
        "heads": 1,
        "max_seq_len": 2048,
        "block_width": 1,
        "num_state_vectors": 1,
        "use_flash_attn": true
  }
  ```

  Configuration for training:
  ```json
  "training": {
        "dataset": { ... },
        "loader": {
            "batch_size": 64,
            "num_workers": 0,
            "prefetch_factor": null
        },
        "checkpoints_dir": "results/pths/",
        "load_checkpoint_name": null,
        "save_checkpoint_name": "debug",
        "n_epochs": 1000,
        "learning_rate": 5e-5,
        "weight_decay": 0,
        "comment": "debug",
        "enable_writer": false
  }
  ```
  Explanation of parameters:
  - `checkpoints_dir`: directory with checkpoints;
  - `load_checkpoint_name`: name of checkpoint to load for training. Leave empty for training from the scratch;
  - `save_checkpoint_name`: name of checkpoint to save after the training epoch;
  - `enable_writer`: enable wandb logging 

  In the configuration of validation and evaluation, the parameter names have the same meaning.

  During model training, the weights are loaded from `checkpoints_dir` using the filename specified by `load_checkpoint_name`. The dataset is generated according to the dataset configuration. The training runs for `n_epoch` epochs. After each epoch, a checkpoint is saved to `checkpoints_dir`. Also, the checkpoint with best NMSE metric is saved.

  During evaluation, the model weights again loaded from `checkpoints_dir` using `load_checkpoint_name`. The evaluation is performed at different SNR values specified by `snr_db`. The resulting NMSE values are written to a text file located in `results_dir`, with the filename composed of `load_checkpoint_name` and `comment`. The first column in the resulting file corresponds to the evaluation SNR values. The second column corresponds to the NMSE values averaged by subcarriers. Following columns provide per-subcarrier NMSE.
